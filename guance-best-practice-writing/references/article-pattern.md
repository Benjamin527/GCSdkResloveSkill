# Guance Learn Style Pattern

Use this file when the user wants the result to feel close to `guance.com/learn`.

## Core characteristics

- Start from a real scenario, not from a menu path
- Explain the practical gain early
- Keep implementation grounded in real product behavior
- Use readable sections rather than dense operator notes
- End with an outcome-oriented summary

## Recommended structure

### 1. Background

Describe who is facing the problem and why the topic matters.

### 2. Why this matters

Summarize 3 to 4 direct gains such as access efficiency, observability coverage, governance, or troubleshooting efficiency.

### 3. Solution overview

Explain the roles, architecture, or integration path in one short section.

### 4. Preconditions

List only the setup items that truly gate success.

### 5. Implementation steps

Use grouped steps. Each step should explain purpose first, then action.

### 6. Validation or effect

Show what success looks like after implementation.

### 7. Common issues or key considerations

Use a small FAQ section when the source material has common failure points.

### 8. Summary

Reinforce the main value and the 1 to 3 critical implementation details.

## Compression rules

- If the article is short, merge "Why this matters" into "Background"
- If the source is mostly configuration, keep one config block and move explanation outside the block
- If the source is heavy on screenshots, convert screenshot meaning into prose first and leave image placement for later

## Tone guide

Prefer:

- "对于已经使用..."
- "完成接入后..."
- "需要重点关注的关键点包括..."
- "在这一过程中..."

Avoid:

- "点击这里"
- "如上图所示" without explanation
- "非常牛"
- "最强"
- Unsupported absolute claims
